## 1. El Ecosistema Alby

Alby ofrece varias herramientas para integrar Lightning payments:

| Paquete | Propósito | Contexto Ideal |
|---------|-----------|----------------|
| `@getalby/sdk` | SDK core con NWCClient | Backend, AI agents, scripts |
| `@getalby/bitcoin-connect-react` | Modal UI para wallets | Web apps con checkout |
| `@getalby/lightning-tools` | Utilities (decode invoices) | Herramientas auxiliares |

### Protocolo NWC (NIP-47)

Nostr Wallet Connect es un protocolo abierto que permite:
- Conectar wallets Lightning a aplicaciones
- Crear/verificar invoices sin custodiar fondos
- Funciona con Alby Hub, coinos, Primal, lnwallet.app

**Connection String Format:**
```
nostr+walletconnect://[pubkey]?relay=[relay]&secret=[secret]
```

## 2. Las Cuatro Opciones

### Option A: Direct NWC (Backend Only)

**Descripción**: Usar `@getalby/sdk` directamente en el servidor para crear y verificar invoices.

```typescript
// src/lib/nwc.ts
import { nwc } from '@getalby/sdk';

const nwcClient = new nwc.NWCClient({
  nostrWalletConnectUrl: process.env.NWC_URL!
});

// Create invoice
const transaction = await nwcClient.makeInvoice({
  amount: 1000, // millisats
  description: 'Order #123'
});

// Check payment status
const result = await nwcClient.lookupInvoice({
  payment_hash: transaction.payment_hash
});
```

| Pros | Contras |
|------|---------|
| Control total del flujo | Requiere polling manual |
| Sin dependencias UI | QR code manual |
| Ideal para bots/agents | Más código a escribir |
| Server-side only (seguro) | Sin WebLN browser support |

**Best For**: Backend integrations, AI agents, CLI tools

---

### Option B: Bitcoin Connect (UI Modal)

**Descripción**: Usar `@getalby/bitcoin-connect-react` para una UI modal que maneja todo.

```typescript
// Install: npm install @getalby/bitcoin-connect-react
import { init, launchPaymentModal } from '@getalby/bitcoin-connect-react';

// Initialize once
init({ appName: 'PROOF OF WEAR' });

// Launch payment modal
const { setPaid } = launchPaymentModal({
  invoice: 'lnbc...',
  onPaid: (response) => {
    // Payment confirmed!
    clearCart();
    router.push('/checkout/success');
  },
  onCancelled: () => {
    // User cancelled
  }
});
```

| Pros | Contras |
|------|---------|
| UI lista para usar | Menos control del diseño |
| Multi-wallet support | Dependencia extra |
| WebLN auto-detection | Modal puede no matchear Neo-Brutalist |
| Handles all edge cases | Client-side payment verification |

**Best For**: Web apps que quieren checkout rápido

---

### Option C: WebLN + Fallback

**Descripción**: Detectar si el usuario tiene una extensión WebLN (Alby extension) y sino fallback a QR.

```typescript
// Check for WebLN provider
if (typeof window.webln !== 'undefined') {
  await window.webln.enable();
  const response = await window.webln.sendPayment(bolt11);
  // Instant payment via extension
} else {
  // Show QR code fallback
  showQRModal(bolt11);
}
```

| Pros | Contras |
|------|---------|
| Mejor UX para power users | Requiere dos flujos |
| Un click payment | Extensiones son minoría |
| Native feel | Más complejo de mantener |

**Best For**: Apps targeting Bitcoin enthusiasts

---

### Option D: Hybrid (A + B)

**Descripción**: Backend NWC para crear invoices + Bitcoin Connect para display.

```typescript
// Backend: Create real invoice via NWC
const invoice = await fetch('/api/invoices', {
  method: 'POST',
  body: JSON.stringify({ orderId, amountSats })
});

// Frontend: Display via Bitcoin Connect
launchPaymentModal({
  invoice: invoice.bolt11,
  onPaid: handleSuccess
});

// Backend: Verify payment via NWC lookupInvoice
// (more reliable than trusting client)
```

| Pros | Contras |
|------|---------|
| Best of both worlds | Más complejo |
| Server-side verification | Dos paquetes |
| Great UX | Potential UI mismatch |
| Maximum compatibility | |

**Best For**: Production e-commerce that wants reliability + UX

## 3. Matriz de Compatibilidad

| Feature | A: Direct NWC | B: Bitcoin Connect | C: WebLN | D: Hybrid |
|---------|---------------|-------------------|----------|-----------|
| Invoice creation | Server ✅ | Client ❌ | Client ❌ | Server ✅ |
| Payment verification | Server ✅ | Client ⚠️ | Client ⚠️ | Server ✅ |
| QR Display | Manual | Built-in ✅ | Manual | Built-in ✅ |
| WebLN support | ❌ | ✅ | ✅ | ✅ |
| Multi-wallet | Via NWC URL | ✅ | Extension only | ✅ |

## 4. Análisis para PROOF-OF-WEAR

### Contexto del Proyecto
- **Stack**: Next.js 16 + React 19
- **Design**: Neo-Brutalist (3px borders, hard shadows)
- **SDK instalado**: `@getalby/sdk@7.0.0`
- **Audiencia**: Early Bitcoin adopters (likely have wallets)

### Preguntas Socráticas

1. **¿Querés control total del diseño?**
   - Sí → Option A (custom QR modal)
   - No → Option B/D (Bitcoin Connect modal)

2. **¿La verificación de pago debe ser server-side?**
   - Sí (más seguro) → Option A/D
   - No (confío en client) → Option B

3. **¿Cuánto tiempo tenés?**
   - Poco → Option B (fastest)
   - Normal → Option A/D

4. **¿Tu UI es muy custom?**
   - Sí (Neo-Brutalist) → Option A
   - No → Option B/D

## 5. Recomendación del Filósofo

### Para PROOF-OF-WEAR: **Option A (Direct NWC)**

**Razones:**

1. **Ya tenés el SDK instalado** (`@getalby/sdk@7.0.0`)
2. **El diseño Neo-Brutalist requiere control** - el modal de Bitcoin Connect no va a matchear
3. **Server-side verification** es crítico para e-commerce real
4. **El código ya tiene estructura preparada** - solo necesitás reemplazar fake con real
5. **Audiencia crypto-native** probablemente tiene Alby Hub configurado

**Implementación recomendada:**
1. Usar `NWCClient.makeInvoice()` en `/api/invoices`
2. Crear `PaymentModal` custom con Neo-Brutalist styling
3. Usar `NWCClient.lookupInvoice()` para verificar pagos (polling)
4. QR code con `qrcode.react` (ya es compatible)

### Alternativa: **Option D** si querés WebLN support

Si querés que usuarios con Alby Extension paguen con un click:
1. Mantener Option A para invoice creation
2. Agregar `launchPaymentModal` de Bitcoin Connect solo para display
3. Verificar siempre en backend (no confiar en client callback)

## 6. NWCClient API Reference

### Methods Needed

```typescript
import { nwc } from '@getalby/sdk';

const client = new nwc.NWCClient({
  nostrWalletConnectUrl: process.env.NWC_URL!
});

// Create invoice (millisats)
interface MakeInvoiceParams {
  amount: number;      // amount in millisats (sats * 1000)
  description?: string;
  expiry?: number;     // seconds until expiry
}

const invoice = await client.makeInvoice({
  amount: 1000 * 1000, // 1000 sats = 1_000_000 millisats
  description: 'Order #123',
  expiry: 600 // 10 minutes
});
// Returns: { invoice: 'lnbc...', payment_hash: '...' }

// Lookup invoice by payment_hash
const status = await client.lookupInvoice({
  payment_hash: invoice.payment_hash
});
// Returns: { preimage: '...' } if paid, otherwise preimage is undefined

// Get balance
const balance = await client.getBalance();
// Returns: { balance: number } in millisats
```
