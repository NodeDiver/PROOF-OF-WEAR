## Overview

This guide covers how to configure NWC (Nostr Wallet Connect) wallets for the PROOF-OF-WEAR Lightning payment system.

---

## Step 1: Choose Your NWC Provider

### Option A: Alby Hub (Self-Custodial) - Recommended

**Alby Hub** is a self-custodial Lightning node that runs on your own hardware.

**Pros:**
- Full control of funds
- No third-party custody
- Professional-grade routing

**Setup:**
1. Install Alby Hub: https://albyhub.com
2. Connect to a Lightning node (LND, CLN, etc.)
3. Navigate to **Settings → Wallet Connections**
4. Click **"Create new connection"**
5. Select permissions: `make_invoice`, `lookup_invoice`, `get_balance`
6. Copy the NWC URL (starts with `nostr+walletconnect://`)

### Option B: Alby Account (Custodial)

**Alby Account** is a custodial Lightning wallet hosted by Alby.

**Pros:**
- Instant setup
- No hardware required
- Free tier available

**Setup:**
1. Create account: https://getalby.com
2. Go to **Developer → Wallet Connections**
3. Click **"Create new connection"**
4. Name it "PROOF-OF-WEAR Production"
5. Select permissions: `make_invoice`, `lookup_invoice`, `get_balance`
6. Copy the NWC URL

### Option C: Other NWC Wallets

These wallets also support NWC:
- **coinos** - https://coinos.io
- **Primal** - https://primal.net (mobile app)
- **lnwallet.app** - https://lnwallet.app

## Step 2: Configure Environment Variables

### Create `.env.local`

```bash
cp .env.example .env.local
```

### Edit `.env.local`

```env
# Production wallet (receives customer payments)
NWC_URL=nostr+walletconnect://[YOUR_PUBKEY]?relay=[RELAY_URL]&secret=[SECRET]

# Optional: Test wallets for E2E testing
NWC_TEST_WALLET_A=nostr+walletconnect://...
NWC_TEST_WALLET_B=nostr+walletconnect://...
```

### NWC URL Format

```
nostr+walletconnect://[pubkey]?relay=[relay]&secret=[secret]
```

| Component | Description |
|-----------|-------------|
| `pubkey` | Wallet's Nostr public key (hex) |
| `relay` | Nostr relay URL (e.g., `wss://relay.getalby.com/v1`) |
| `secret` | Shared secret for authentication |

## Step 3: Required NWC Permissions

Your NWC connection needs these methods enabled:

| Method | Purpose |
|--------|---------|
| `make_invoice` | Create Lightning invoices for orders |
| `lookup_invoice` | Check payment status (polling) |
| `get_balance` | Display wallet balance (optional) |

---

## Step 4: Security Considerations

### Do's

- Store NWC_URL in `.env.local` (gitignored)
- Use read-only permissions when possible
- Set budget limits in NWC connection settings
- Rotate connection strings periodically

### Don'ts

- Never commit NWC URLs to git
- Don't share NWC URLs publicly
- Don't use admin/full-access connections for production

### Budget Limits

When creating your NWC connection, consider setting:
- **Max amount per transaction**: 100,000 sats (or your max product price)
- **Daily budget**: 1,000,000 sats (adjust based on expected volume)
- **Connection expiry**: 1 year (forces periodic rotation)

## Step 5: Test Your Configuration

### Start Dev Server

```bash
npm run dev
```

### Verify Connection

1. Navigate to `/pipeline-test`
2. Click "Run Test Payment"
3. If invoice creation succeeds, your NWC is configured correctly
4. Scan QR with a Lightning wallet to complete the test

### Common Errors

| Error | Cause | Solution |
|-------|-------|----------|
| "NWC_URL environment variable is required" | Missing .env.local | Create and configure .env.local |
| "Failed to create invoice" | Invalid NWC URL | Check URL format and permissions |
| "Connection timeout" | Relay unreachable | Try a different relay URL |
| "Insufficient permissions" | Missing methods | Add make_invoice permission |
